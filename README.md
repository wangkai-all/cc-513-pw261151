# 隐私保护聚合查询服务

一个零外部依赖的 Node.js 服务：对员工数据做聚合查询时，用 **k-匿名阈值**、**Laplace 差分隐私噪声**、**每调用方 ε 预算**、**重复查询上限** 与 **结果缓存** 控制信息披露，并把每一次发布、缓存命中与拒绝都写进 **可校验的哈希链审计日志** 和 **预算台账**。

前端是一个中文界面，展示查询条件、隐私状态、剩余预算和具体拒绝原因；`<details>` 折叠区内是运维控制台（策略调整、调用方权限撤销、审计链校验、台账查询）。

## 快速开始

```bash
node --version         # 需要 >= 22.5（使用内置 node:sqlite）
npm start              # http://127.0.0.1:5173，首次启动自动灌入确定性演示数据
npm test               # 55 个测试：引擎 / HTTP / 前端契约 / 前端运行时
npm run demo           # 临时数据库上跑一遍全部保证，打印可读报告
```

常用环境变量：`PORT`（默认 5173）、`HOST`（默认 127.0.0.1）、`DB_PATH`（默认 `data/privacy.sqlite`）。重置数据：删掉 `data/privacy.sqlite*` 后重启。

演示调用方（`X-Caller-Id` 头）：

| 调用方 | 权限 | 用途 |
| --- | --- | --- |
| `analyst-hr` | 聚合 + 计数 + 指标，全部地区 | 主路径 |
| `analyst-fin` | 聚合 + 指标（**无计数**） | 演示指标级授权 |
| `analyst-regional` | 聚合 + 计数，**仅华东** | 演示地区范围 |

所有查询逻辑都在一个 `BEGIN IMMEDIATE` 事务里完成，并发请求被串行化，因此两个同时到达的查询不可能一起花掉最后一单位预算。

## 判定流水线

一次查询按固定顺序检查，任一步失败即拒绝，并且 **拒绝一律免费（ε=0）但仍写入台账与审计**，探测行为因此可见且受重复查询限制：

1. 请求格式合法 → `denied_invalid_request`（HTTP 400，带具体字段错误）
2. 调用方存在且未被撤销 → `denied_caller_not_found` / `denied_caller_inactive`
3. 客户端回显的权限版本与服务端一致 → `denied_stale_authority`
4. 持有 `query:aggregate` + 指标权限，且地区在授权范围内 → `denied_permission`
5. 群体大小 ≥ k（先按地区授权收窄） → `denied_k_threshold`
6. 每个非空分组单元格 ≥ k → `denied_complementary_suppression`
7. 与历史已发布群体的一侧差集不小于 k → `denied_differencing`
8. 相同策略版本 + 查询 + 数据签名已有缓存 → `cached`（免费，不是拒绝）
9. 同条件在窗口内尝试次数未超限 → `denied_repeat_limit`
10. 剩余预算足够 → `denied_budget_exhausted`
11. 发布：加噪、计费、记录群体曝光、写缓存、写审计链。

注意差分防护排在缓存之前：缓存按查询共享、与调用方无关，但每个调用方必须以**自己的**已发布历史做差分判断。否则调用方 A 预热缓存后，调用方 B 可能拿到一个相对于 B 的历史会泄露少于 k 人的答案（有专门的回归测试覆盖）。

### 为什么「切换筛选/权限后重新判断」

- **策略版本**：任何隐私相关策略改动都会 `policy.version += 1` 并清空缓存；缓存键包含策略版本，旧答案不可能在新策略下被重放。
- **调用方版本**：权限或启用状态变更时 `callers.version += 1`。客户端在请求里回显 `callerVersion`，不一致直接 `denied_stale_authority`，不执行也不收费。服务端从不信任客户端声明的权限。
- **缓存不是后门**：缓存命中前，身份、启用状态、版本、权限、地区范围、k 阈值、互补抑制、重复限制、差分防护全部照常执行。权限被撤销后，即使答案还在缓存里也会被拒绝（测试覆盖）。
- **数据变化**：缓存条目记录底层行的 `cohortSignature`（人员 ID、地区、部门、年龄段、司龄、薪资的哈希）。薪资或归属变动会让签名失配，从而自然失效。

### 为什么拆分查询绕不过阈值

- **互补抑制**（默认开）：按维度分组时，只要有一个非空单元格 < k，**整次查询拒绝**。若只隐藏小格，隐藏本身就泄露了「这里有个小群组」。被抑制的标签只出现在运维审计里，不返回给用户。
- **差分防护**：记录每个调用方已经拿到答案的群体成员集合（按指标区分）。新群体与任一历史群体做**单侧差集**：`A\B` 与 `B\A` 中任一非空且 < k 时拒绝——否则两个答案相减就能孤立出这几个人。完全相同的群体不算差分风险（由重复上限与预算治理）；两个都 ≥ k 的嵌套群体是安全的，允许。
- **粗化群体规模**：拒绝响应只给 `cohortBand`（`empty` / `below_k` / `small` / `large`），不给精确人数，防止用一连串拒绝二分出小群体大小。

### 预算与机制

- 计数：敏感度 1；有界均值：敏感度 = `(max − min) / 组内真实人数`（薪资 3 万–22 万，司龄 0–30 年）。噪声尺度 = 敏感度 / `perQueryEpsilon`，用 Laplace 逆 CDF 采样。
- 一次查询的成本 = `perQueryEpsilon × 实际发布的单元格数`（被抑制的格不计费）。小数 ε 用 1e-9 容差比较，记账精确。
- 台账对 `(caller_id, request_id)` 唯一：同一个请求编号重放返回**首次发布的原始快照**（`replayed`），不会再次采样、不再计费，也不能把一次发布拆成两次。

### 审计链

`audit_log` 每行包含 `prev_hash` 与前一行哈希 + 本行规范化 JSON（键排序）的 SHA-256。SQLite `BEFORE UPDATE/DELETE` 触发器直接 `RAISE(ABORT)`。`verifyAuditChain()` 从头重算，能发现修改、删除与重排；测试里通过临时删触发器模拟数据库级篡改，确认能被检出。

审计记录区分两类读者：

- **运维可见**：精确群体人数、被抑制单元格的标签与人数、敏感度、噪声尺度、发布后累计预算。
- **调用方可见**：只有粗化 band、k、本次计费、拒绝原因码。拒绝详情字段在 `publicDenialDetails()` 中白名单化。

## HTTP 一览

```text
GET  /api/health                    健康检查：员工数、审计链状态、缓存统计
GET  /api/meta                      指标、维度、分组项、当前策略、调用方列表
GET  /api/me                        当前调用方、预算（已用/上限/剩余/单组成本/还可发布组数）、版本
GET  /api/me/history                我的台账与审计
GET  /api/me/cohorts                我已获得过答案的群体规模列表
POST /api/query                     { query: { metric, groupBy, filters, requestId?, callerVersion? }, note? }
GET  /api/admin/overview            策略、缓存、审计链、调用方预算汇总
GET  /api/admin/audit?limit=&actor=
GET  /api/admin/audit/verify        重算哈希链
GET  /api/admin/ledger?caller=&limit=
POST /api/admin/policy              修改策略（审计 + 版本递增 + 清缓存）
POST /api/admin/cache/purge         手动清空缓存
POST /api/admin/cache/purge-expired 清理过期/旧版本缓存
POST /api/admin/callers/:id/revoke | restore | permissions
```

**拒绝是结构化结果，不是 HTTP 错误**：策略性拒绝返回 `200` 与 `privacy.status = "denied"` / `reasonCode`，前端据此渲染原因。只有语法/参数错误返回 `400 invalid_query`（响应体仍附完整 `result`，并带具体字段提示）。这样调用方能统一处理「允许但需解释」与「请求本身有问题」。

管理接口用 `X-Admin: 1` 头做演示级门禁——生产环境应替换为真实身份与角色校验（见下文限制）。

## 前端

- 查询表单：指标、分组维度、三个筛选条件、备注。
- 结果卡片：隐私状态、原因说明、k、此次计费、策略版本、缓存状态；下方表格与「条件」标签（`隐私引擎` / `查询条件` 汇总）。
- 预算面板：已消耗/上限进度条、单组成本、还可发布组数。
- 历史表：每次尝试的结果、计费、时间。
- 运维控制台：策略表单（全部字段有上下界校验）、调用方权限开关、审计链校验、缓存统计、审计与台账明细。
- 安全约束：只用 `textContent` / `createElement`，测试会拒绝 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`；静态服务发送 CSP（`script-src 'self'`）并拒绝目录穿越；无 SPA 回退，miss 返回 404 JSON。

## 测试

```bash
npm test
```

覆盖要点（55 项）：

- **发布与计费**：首次发布计费、缓存免费、幂等重放免费且字节一致、小数 ε 精确。
- **阈值**：低于 k 拒绝且免费、拒绝不泄露精确人数或标签、无地区授权 → 空群体。
- **互补抑制**：分组含小格整单拒绝、被抑制标签不出现在响应里。
- **差分**：窄差集拒绝、新增大群体允许、两个都 ≥ k 的嵌套群体允许、不同指标互不影响、**共享缓存不能绕过差分防护**（重启预热 + 攻击者有历史）。
- **重复与预算**：重复上限、预算耗尽与缓存的关系、并发 12 个请求在 3 次预算内恰好放行 3 次、两个引擎共享同一数据库时不能同时花掉最后 1 ε。
- **权限**：撤销立即生效（含缓存）、恢复递增版本、过期 `callerVersion` 先于权限错误返回、改权限后旧筛选被拒。
- **缓存失效**：策略版本变化、底层行变化（改薪资）、手动清理、过期清理。
- **审计**：所有结果都会记录、物理不可改（触发器）、篡改可检出。
- **HTTP**：缺调用方 401、拒绝为 200、非法查询 400、坏 JSON 400、并发预算、管理接口门禁、静态资源 CSP、目录穿越 404。
- **前端**：`app.js` 引用的每个 id 都存在、覆盖全部结果码、策略表单字段齐全；并用一个手写迷你 DOM 真正启动 `app.js`，跑通「发布 → 拒绝 → 预算面板」的渲染路径。

`npm run demo` 是同一套保证的可读版本，适合评审时快速过一遍。

## 已知限制（演示范围）

这是一个完整可运行的教学/评审实现，以下部分有意简化：

- **身份认证**：`X-Caller-Id` 由客户端自报，`X-Admin: 1` 直接放行。生产环境必须替换为会话/令牌与真实角色校验；服务端其余逻辑已经是「以服务端记录为准」的写法，替换认证层不影响隐私判定。
- **单进程并发控制**：串行化依赖 SQLite 的 `BEGIN IMMEDIATE`，多进程共用一个数据库时依赖数据库锁（已有一个测试覆盖双引擎场景）。换成 Postgres 时应把预算检查放进 `SELECT ... FOR UPDATE` 或序列化事务。
- **差分防护的规模**：每个调用方保留已发布群体的成员集合，复杂度随历史群体数线性增长；大规模部署需要近似数据结构或按时间窗回收。
- **噪声与取整**：计数结果取整并截断到 ≥ 0，均值保留两位小数。这些后处理在小计数上会略微改变严格的 ε 保证，属于常见的工程折中；若要严格形式化，应在发布前做后处理感知的预算核算。
- **合成数据**：员工数据由固定种子生成，仅用于演示，不包含任何真实个人信息。

## 设计取舍

- **拒绝返回 200**：客户端只需要一条渲染路径；HTTP 状态码留给真正的传输/格式错误。
- **缓存与调用方无关**：答案只取决于数据、查询和策略，因此可以共享；但每次命中仍要重新过一遍权限、预算与曝光检查。这样既省算力，又不把共享缓存变成越权读取通道。
- **审计与用户响应分离**：审计保存判定所需的一切（精确人数、标签、噪声参数），响应只保留回答用户「为什么被拒绝」所必需的最少信息。
- **零依赖**：`node:sqlite`、`node:crypto`、`node:http`、`node:test` 足够，部署时没有供应链与安装成本。
